# 小厨云端多用户与 Android App 设计

日期：2026-09-02

## 目标

把当前仅在 Windows 本机运行的小厨 PWA 改造为可供少量受邀测试者使用的云端应用，并生成可直接安装的 Android APK。网页版和 APK 共用同一套云端账号、食谱、个人数据和 AI 服务。测试阶段使用阿里云杭州 Ubuntu 22.04 ECS（2 核 4 GiB）及公网 IP；以后可平滑切换到已备案域名。

## 已确认范围

- APK 内置 React 前端，不使用只加载远程网页的纯 WebView 壳。
- 云服务器同时提供登录后的网页版和 API。
- 10,520 道食谱、分类和食谱图片缓存由所有用户共用。
- 收藏、最近浏览、冰箱、购物清单和 AI 对话按账号隔离。
- 采用邀请制注册，不开放任意注册，不接短信、邮箱、付费和找回密码。
- AI 模型及 Key 由管理员统一配置；测试用户共享模型但受个人额度和频率限制。
- 测试阶段通过公网 IP 和可信 HTTPS IP 证书访问；若阿里云限制未备案 Web 服务，则切换 Tailscale 作为备用通道。
- 目前只做 Android，不做 iOS 和应用商店正式发布。

## 总体架构

Android APK 内置 HTML、CSS、JavaScript、路由、页面样式和 Capacitor 原生桥接。它通过可配置的 `https://<公网 IP>` 调用云端 API。服务器上的 Nginx 终止 HTTPS、提供网页版静态资源并把 `/api` 转发给只在 Docker 内部网络监听的 Node/Fastify 服务。Node 服务访问持久化 SQLite、共享食谱目录、图片缓存和加密模型配置，并代替客户端调用 DeepSeek、通义千问或其他 OpenAI 兼容模型。

APK 不是纯壳：服务器离线时仍可打开内置界面和服务器设置，但登录、云端食谱、个人数据、图片识别和 AI 功能不可用。测试版不增加完整离线食谱库。

云端同时保留网页版。电脑用户可通过同一 HTTPS 地址登录，网页版和 APK 使用相同账号及数据。服务器没有通过认证的请求不能读取个人数据或调用 AI。

## 身份认证与权限

首次部署通过一次性管理命令创建管理员。管理员可以生成和撤销一次性邀请码、禁用测试账号、重置账号密码、撤销登录会话、管理模型、调整 AI 限额和查看聚合调用量。测试用户只能访问自己的个人数据。

用户使用邀请码、用户名和密码注册。密码使用 Node 内置 `scrypt`、独立随机盐和恒定时间比较进行哈希验证，数据库不保存明文密码。账号角色仅有 `admin` 与 `tester`。

网页版使用 Secure、HttpOnly、SameSite Cookie。Android 使用短时访问令牌和可撤销刷新令牌；刷新令牌保存在 Android Keystore，访问令牌只保存在运行内存。退出登录、账号禁用或管理员撤销会使刷新令牌失效。所有登录、注册、刷新、管理和个人数据接口均有速率限制。

## 数据模型与隔离

新增用户、邀请码、登录会话、每日 AI 用量及审计事件表。现有个人数据表增加非空 `user_id` 外键及以用户为首列的查询索引。所有个人数据仓储都必须从经过认证的请求上下文取得 `user_id`，不接受客户端任意指定用户 ID。

食谱、分类和封面清单保持共享，不重复存储。模型配置保持全局管理员资源。AI 会话和消息归属单一用户；读取上下文、冰箱和购物清单时同时验证资源所有者。

现有本地数据迁移时创建管理员账号，并把原收藏、浏览记录、冰箱、购物清单和聊天记录归入该管理员。迁移前自动备份数据库；失败则整笔回滚，不留下部分迁移状态。

测试阶段继续使用单实例 SQLite 和持久化磁盘。所有写事务保持短小，启用 WAL、外键和忙等待。该设计适用于当前单台 2 核 4 GiB ECS 和少量测试用户；不把它描述为面向大规模公开运营的终态。

## AI 配置与额度

模型 Key 只在服务端接收、加密和使用，不返回给网页版或 APK。原 Windows DPAPI 存储替换为跨 Ubuntu 可用的 AES-256-GCM 信封格式；每条密文使用独立随机 nonce。主密钥保存在宿主机 root 专属、权限为 `0600` 的 `/srv/xiaochu/secrets/app-master-key`，以只读 Docker secret 挂载到应用容器，不进入 SQLite、日志、镜像或 Git。

默认每个测试账号每天最多 100 次 AI 提问、每分钟最多 10 次，管理员可修改。服务端在调用上游模型前以事务方式检查并登记额度，避免并发绕过。超额、鉴权失败、模型余额不足、上游限流和网络超时返回稳定错误码与中文提示，不泄露 Key、令牌或上游完整响应。

## 云服务器部署

仓库新增生产 Dockerfile、`compose.yaml`、Nginx 配置、Ubuntu 初始化脚本、部署脚本、数据库备份与恢复脚本、证书申请与续期脚本、环境变量模板和运维手册。生产镜像使用 Node 24 LTS 兼容基础镜像，构建 `better-sqlite3` 与 `sharp` 所需的二进制依赖。

服务器持久化目录固定为：

```text
/srv/xiaochu/app
/srv/xiaochu/data
/srv/xiaochu/covers
/srv/xiaochu/backups
/srv/xiaochu/certbot
/srv/xiaochu/logs
/srv/xiaochu/secrets
```

阿里云安全组与 Ubuntu 防火墙只开放 22、80、443。SSH 端口优先限制为管理员当前公网地址；4173、数据库和容器内部端口不开放。Nginx 提供安全响应头、请求体上限和登录/API 限流；Node 容器只接受内部网络流量。服务提供无需敏感信息的健康检查。

公网 IP 使用 Certbot 5.4+ 和 Let’s Encrypt `shortlived` 配置申请 IP 地址证书。定时任务每天多次检查续期，成功后原子更新证书并重新加载 Nginx；续期失败保留现有证书并产生明确日志。若阿里云阻止未备案公网 Web 访问，不降级到明文 HTTP，而是启用 Tailscale 备用访问。

## 备份、恢复与更新

每天执行 SQLite 一致性检查和在线备份，保留最近 7 份每日备份与 4 份每周备份。每次部署和迁移前额外备份。恢复脚本先验证目标文件，再停止写入、恢复并执行迁移与健康检查。AES 主密钥单独离线保存，不与数据库备份放在同一位置。

更新流程为：备份、构建新镜像、执行迁移、启动、检查健康与关键接口；失败则回滚上一镜像和迁移前备份。食谱、用户数据、图片缓存和密钥文件均不随容器更新被覆盖。

以后取得已备案域名时，为域名添加 A 记录和普通 HTTPS 证书，Nginx 在迁移期同时接受 IP 与域名。Android 登录页允许修改并测试 HTTPS 服务器地址；切换地址后重新登录，不删除云端个人数据。IP 入口保留过渡期后关闭。

## Android App

使用 Capacitor 8，应用名为“小厨”，包名为 `com.xiaochu.cooking`，目标 Android 16/API 36，最低 Android 7/API 24，重点验证 Android 10 至 16。PWA 的 service worker 仅用于网页版；Capacitor 构建不注册 service worker，避免旧资源缓存覆盖 APK 内置版本。

Android 仅声明网络、相机和麦克风权限。相机权限在拍摄冰箱照片时申请；麦克风权限在用户主动开始语音提问时申请。拒绝权限后仍可文字提问和手动选择图片。不申请通讯录、定位、短信、电话、后台麦克风或全部文件访问。

冰箱拍照使用 Capacitor Camera。语音助手使用小型原生桥接调用 Android SpeechRecognizer 与 TextToSpeech，流程为“点击说话、识别文本、发送 AI、流式显示、朗读回答、允许打断”；不持续后台监听。登录页提供 HTTPS 服务器地址、测试连接、保存和重置功能，正式构建拒绝 HTTP 地址。

构建产生调试 APK、使用固定发布密钥签名的测试 APK，以及为未来商店准备的 AAB。发布密钥与密码不进入仓库，至少保存两份离线备份。签名 APK 可由服务器提供下载，同时发布 SHA-256 校验值。测试人员通过邀请码注册；覆盖安装同签名新版不会删除云端数据。

## 错误处理与可观察性

Android 与网页版统一处理离线、服务器不可达、证书错误、登录过期、权限拒绝、额度耗尽和上游模型错误。证书错误不得提供“忽略并继续”。网络恢复后允许用户手动重试，不自动重复提交可能产生副作用的请求。

服务端日志包含请求 ID、匿名化用户 ID、路由、状态码、耗时和错误码，不记录密码、令牌、API Key、完整聊天正文或上传图片。管理员可以查看健康状态、证书剩余时间、磁盘空间、备份时间和聚合 AI 用量。

## 验证范围

- 云端迁移：现有个人数据归入管理员，失败可回滚。
- 认证：邀请码一次性、密码哈希、登录刷新、退出、禁用账号和撤销会话。
- 隔离：两个测试账号无法读取或修改对方的任何个人资源或聊天记录。
- AI：统一模型 Key、每日额度、分钟限流、流式回复和安全错误提示。
- 部署：全新 Ubuntu 主机可按手册完成部署，只有 22/80/443 对外，容器重建不丢数据。
- HTTPS：公网 IP 证书可申请、自动续期并在 Nginx 生效；失败不降级 HTTP。
- 备份：备份文件通过一致性检查，可在干净目录完成恢复。
- Android：API 36 构建通过，签名 APK 可安装；登录、食谱、收藏、相机、购物清单、AI 文字及语音在真实设备完成冒烟验证。
- Web：通过公网 HTTPS 登录后可使用与 APK 相同的数据和账号。

## 非目标

- 不在本阶段支持公开注册、短信、邮件、找回密码、支付、订阅和应用商店上架。
- 不在本阶段实现 iOS、完整离线食谱、跨服务器集群或 PostgreSQL 迁移。
- 不把 AI Key 下发给测试用户，也不允许测试用户自行配置模型。
- 不通过明文 HTTP 传输账号、个人数据或 AI 请求。
