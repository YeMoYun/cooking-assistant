# AI 助手模型切换与回复流修复设计

日期：2026-09-02

## 目标

- AI 助手页面可选择任一已启用的文本模型，并提供“添加/管理模型”入口。
- 切换模型后保留当前聊天记录，新模型能读取既有对话并继续回答。
- 修复回复流刚建立就被服务端误判为客户端断开的故障。
- 模型或网络失败时显示明确错误，不再留下空白助手消息或无限省略号。

## 已确认根因

当前服务端同时监听 `request.raw` 的 `aborted` 与 `close`。Node 在请求体处理结束后可能触发请求对象的 `close`，即使响应连接仍然有效；该监听随后立即中止模型流。数据库中的最近多次助手消息均为 `cancelled`、内容长度为 0，与这一时序一致。

模型下拉框已经存在，但本地目前只有一个已启用的文本模型，所以用户无法实际切换，也缺少直接添加第二个模型的入口。

## 设计

### 会话与模型切换

新增受保护的会话模型更新接口。它只允许更新仍处于 `active` 状态的会话，并校验目标配置存在、已启用且属于文本模型。更新同一条会话的 `provider_id`、提供商名称和模型快照，不删除 `voice_messages`，因此后续请求仍会从该会话读取最多 24 条历史消息。

前端在没有会话时只更新待使用的模型；已有会话时调用更新接口。切换成功后保留当前转录内容、输入框和上下文选项。模型正在生成回复时禁用选择器，避免一轮回复中途换模型。模型列表旁增加“添加/管理模型”链接，跳转现有模型与密钥页面。

### 回复流生命周期

保留请求对象的 `aborted` 监听，用于请求确实被客户端中断的情况；移除请求对象的普通 `close` 监听，改为监听响应对象的 `close`。仅当响应尚未正常结束时才取消活动模型请求。正常完成时先解除监听，再结束响应。

### 错误呈现

服务端把已知模型错误转换为安全的错误代码和中文消息写入 `turn.error`；未知错误保留通用提示，不泄露 API Key 或上游响应正文。前端收到 `turn.error` 后抛出包含该消息的错误，移除仍为空的助手占位消息并显示错误提示。已有部分回复时保留已接收文本。

## 数据流

1. 页面读取所有已启用文本模型。
2. 用户选择新模型；若已有会话，前端更新该会话的模型配置。
3. 用户发送问题，服务端读取同一会话的历史消息，并使用当前模型生成 NDJSON 流。
4. 文本增量实时写入当前助手消息；正常完成后进入空闲状态。
5. 客户端真正断开才取消流；模型错误则通过 `turn.error` 明确返回。

## 验证范围

- 服务端回归：请求体正常关闭不会取消回复流；客户端断开仍会取消。
- 服务端回归：活跃会话可切换到另一个已启用文本模型，并保留历史消息；无效或禁用模型被拒绝。
- 前端回归：收到 `turn.error` 会显示消息并清理空助手占位；切换模型不会清空转录。
- 编译与现有测试通过。
- 使用本地已配置模型进行一次真实问答，确认收到非空回复；再在配置第二个模型时验证切换后可继续利用历史上下文。

## 非目标

- 不在助手页直接编辑 API Key、Base URL 或 Model ID；这些仍由“模型与密钥”页面管理。
- 不允许在模型仍在生成时强制切换。
- 不修改语音识别或语音合成供应商。
